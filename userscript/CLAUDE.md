# 올인원 개발지침

대상: `roll20-layout2-allinone.user.js` — Roll20 GM용 올인원 유저스크립트.
사람과 Claude 모두 이 문서를 따른다. 지침을 바꿀 때는 이 문서부터 고친다.

## 0. 진행 방식

- 큰 작업은 **요구사항 → 목업(그림) → 계획 → 승인 → 코드** 순서. 승인 전에는 코드를 쓰지 않는다.
- 화면이 바뀌는 일은 목업으로 먼저 합의한다.
- 확실하지 않으면 추측해서 만들지 말고 필요한 것만 묻는다.
- 기존 코드를 존중한다. 불필요한 리팩터링 금지. 새 기능 전에 다시 쓸 수 있는 코드부터 찾는다.
- 버그는 최소 수정. 잘 되는 곳은 건드리지 않는다.
- 검증된 오픈소스가 있으면 직접 만들기 전에 먼저 제안한다 (유지보수 상태 · 의존성 확인).
- 설명은 짧게, 결론과 필요한 코드만.

## 2. 코드 구조

- 기능 하나 = FEAT 모듈 (`inject` · `setEnabled` · `watch`). 묶음은 `addBundle`.
- 새 창은 `AIO_ZOOMED`에 넣는다 (글자 크기 확대가 먹게).
- 공용 함수를 먼저 쓴다: `aioToast`(알림) · `el` · `escAttr` · `copyText` · `r20img` · `sizedUrl` · `grpDrop` · `tblHead` · `tblSections` · `aioErr` · `btnVisible`.
  - 캐릭터 시트 값: `aioAttrs.load(캐릭터)` (시트를 연 적 없는 캐릭터는 속성이 비어 있다 → 받아 온 뒤에 읽는다) · `aioAttrs.find(캐릭터, 이름)`.
  - 채팅에 대신 올리기: `chatPost(글)` (쓰던 글 · 한글 조합을 지킨다) · 값은 `chatPost.safe(값)` 으로 풀어서 넣는다.
- 이름 앞머리: 기능별 `r20xx-`, 공용 부품은 `aio-`.
- 저장 키: `localStorage` `r20_<기능>_<항목>`. 읽기는 `aioPref.get(키)` · 켜고 끄기는 `aioPref.on(키)`(기본 켬), 실패해도 되는 쓰기는 `aioPref.set(키, 값)`.
  실패를 알려야 하는 쓰기(큰 자료 등)만 `localStorage.setItem` 을 try/catch 로 직접.
- 설정 줄(이름 + 값 고르기)은 `aioSegRow(이름, 설명, [[값, 글]…], get, set)`.
- 방 데이터(핸드아웃 · 매크로 · 굴림표)에 쓸 때는 저장 버튼을 거치고, 저장 전에는 되돌릴 수 있게.
- 주석은 한국어로 짧게. '무엇'보다 '왜'.

## 3. CSS 규칙

- 색 · 글자 크기 · 높이 · 모서리 · 겹침 층 · 그림자는 `--aio-*` 변수만 쓴다. 새 hex 금지.
  - 글자: `--aio-fs-xs/sm/md/lg/xl` (10 · 11 · 12 · 13 · 15px). 예외는 아이콘 글리프 8 · 9px, 큰 숫자 · 이모지 20 · 21px.
  - 강조색을 옅게 쓸 때는 `color-mix(in srgb, var(--aio-accent) n%, transparent)` — 강조색을 바꾸면 같이 바뀐다.
  - 단추는 공용 부품 `.aio-btn` · `.aio-chip` 부터 (크기는 .sm / .lg, 강조는 .pri). 창마다 단추 모양을 새로 쓰지 않는다.
  - 공용 부품 (CORE_CSS `:is(html, #r20be)` 블록 — id 급이라 창의 `#창 button` 보다 앞섬, 자리마다 고칠 때는 `#창 .이름`):
    `.aio-ib`(✕ · 아이콘 22) · `.aio-sw`(스위치 26×14) · `.aio-seg`(값 고르기) · `.aio-tabs`(화면 바꾸기) · `.aio-in`(입력칸)
    · `.aio-th`(썸네일) · `.aio-tag`(꼬리표) · `.aio-empty`(빈 칸 안내). 고른 카드는 강조색 테두리 2px + `--aio-accent-bg`.
  - 새 창은 CORE_CSS 의 창 틀 · 머리줄 규칙 목록에 id 를 더한다 (창 규칙에 테두리 · 그림자를 다시 쓰지 않는다). 숨김은 `AIO_ROOTS` 에 뿌리를 더하면 된다.
  - 흐림은 .4(못 누름) · .6(흐리게)만.
  - 그림자: `--aio-shadow-sm`(작은 것) · `-md`(펼침 · 메뉴) · `-lg`(창 · 알림). inset 등 특수한 것만 직접.
  - 겹침 층: `--aio-z-dock` < `-win` < `-pop` < `-tip` < `-toast`, 같은 층 안 순서는 `calc(var(--aio-z-win) + n)`. 창 안에서만 쓰는 1~20 은 숫자.
- `!important`는 Roll20 요소 · Roll20 스타일을 덮어써야 할 때만, 이유를 주석으로. 올인원이 만든 요소에는 새로 쓰지 않는다 (우선순위는 선택자로).
- 값이 바뀔 수 있는 CSS 정리는 `node tests/style-snap.js 옛판 새판` 으로 올인원 창 안 계산된 모양을 견준다 ('다른 요소 0개').
- CSS 중첩 (v1.91.0 부터): 같은 앞머리로 시작하는 규칙은 그 앞머리 블록 안에 넣는다.
  - 안쪽 선택자는 늘 `&` 로 시작 (`& .x` · `&:hover` · `& > b`). `&` 없이 쓰지 않는다 (Chrome 120 전에는 깨짐).
  - 앞머리(바깥 선택자)는 쉼표 없는 선택자 하나 · `::before` 같은 가상 요소 없이. 목록이면 `&` 가 가장 센 것의 구체성을 따라가 순위가 바뀐다.
  - 두 겹까지만. 바깥 블록에는 선언을 두지 않거나 맨 앞에만 둔다 (안쪽 규칙 뒤에 선언 금지).
  - `${…}` 가 든 규칙 · `@media` 등 · share-cut 주석은 블록을 가로지르지 않는다 (배포판에서 잘라 낼 때 괄호가 깨짐).
  - 규칙을 옮기거나 묶은 정리는 `node tests/cssom-same.js 옛판 새판` 으로 확인 — 브라우저가 읽은 규칙을 펼쳐 차례 · 선택자 · 선언을 견준다 ('같음').
    덤으로 앞 줄 찌꺼기 등으로 브라우저가 버린 규칙도 수가 달라져 드러난다.
- 공용 부품(`aio-`)이 있으면 그것을 쓰고, 없으면 공용으로 만든다.
- 14인치 노트북 기준으로 슬림하게. 좁은 폭에서도 가로 넘침 없게.
- 크기 조절 손잡이는 아이콘(↔)만. 색 막대 금지.
- Blood Moon 시트 CSS는 ASCII만.

## 4. UX 규칙 — 새 기능 · 고치는 기능 모두 늘 지킨다

다섯 원칙:

1. **창 틀은 하나**: 모든 창이 같은 머리줄 순서 **⠿ 끌기 · 제목 · (창마다 동작) · 자리 · 📌 · ✕**, 같은 끌기(`aioDrag`), 같은 자리 고르기(`aioDockSeg` — 붙임 · ½ · 떠 있기 중 그 창이 되는 것만)를 쓴다. 찾기 칸은 머리줄 아랫줄. 새 창도 이 틀로 만든다.
   - 틀을 안 쓰는 것: 단추 옆에 잠깐 뜨는 **펼침 창**(포트레이트 권한 · 이모지 · 묶음 드롭다운 등 — 바깥 누르면 닫힘)과 **모달**(시트 촬영). 이것들도 제목 · ✕ 순서와 Esc 닫기는 지킨다.
2. **알림은 하나**: 저장 · 복사 · 실패는 공용 알림으로 알린다. 되돌리기 어려운 동작에는 알림에 [되돌리기]를 준다.
3. **키보드 하나로**: 모든 기능을 빠른 찾기(Ctrl+F) 창에서 명령으로도 실행할 수 있게 등록한다. 단축키가 있으면 툴팁에 함께 적는다.
4. **설정은 쓰임새대로**: 새 설정은 쓰임새(세션 진행 / 준비 / 화면) 아래에 두고 설정 찾기에 걸리게 한다.
5. **누구나 읽고 쓸 수 있게**: 글자 대비 4.5:1 이상, '움직임 줄이기' 대응, 키보드 포커스가 보이게.

그 밖에:

- Esc 닫기, ↑↓ Enter 고르기. 입력칸에서는 Roll20 단축키가 먹지 않게 (`stopPropagation`).
- 아이콘 단추에는 `aria-label`과 툴팁.
- 사용자가 고른 것은 기억한다 (창 위치 · 크기 · 고른 묶음 등).
- 실패는 조용히 숨기지 않고 보이게 표시한다 (예: 안 열리는 그림 → "그림 안 열림" 칸).
  숨기면 사용자는 기능이 고장 난 줄 안다.
- 되돌리기 어려운 동작은 확인을 받거나 되돌리기를 준다.

## 5. 성능

- MutationObserver는 좁은 범위만, 몰아서 처리.
- 그림은 `loading="lazy"`, 썸네일 우선.
- 큰 목록은 보일 때만 그린다.
- 옆 서랍(v1.113.0 `makeDrawer`): 주크박스(`jbDrawer`, p=jbd) · 저널(`jnDrawer`, p=jnd)이 같은 틀 — 저장 키 `r20_<p>_*`, 요소 `r20-<p>-*`,
  `body.r20<p>-open`, CSS 는 `drawerCss(p, pane, 머리줄 높이)`. 같은 자리라 한 번에 하나만(`DRAWERS`). 단추줄 · 매크로 · 말하는 사람 고르기는
  `FEAT.jbDrawer?.leftEdge?.() ?? FEAT.jnDrawer?.leftEdge?.()` 로 열린 서랍을 따른다.
- 스크롤 막대(v1.113.1): `AIO_SCROLL_CSS`(::-webkit-scrollbar 6px · 물려받는 scrollbar-color 를 auto 로 끊음 · Roll20 이 thin 을 준 .ui-dialog 등은 auto) 하나로. 요소에 `scrollbar-width` 를 주면 그 요소만 브라우저 thin 이 되므로 쓰지 않는다
  (숨길 때만 `none`). 시트(iframe) 안 문서에는 `sbFrames` 가 같은 글을 넣는다.
- 움직이는 그림(v1.112.0 `mapAnim`): 맵 · 토큰 webm 은 문서 밖 `<video>` 를 Babylon(`#babylonCanvas`)이 매 프레임 `texImage2D` 로 올린다
  (실제 방 13~14개 · 3초에 약 1,150회). 멈추면 Roll20 이 곧바로 `play()` 를 다시 부르므로 `HTMLMediaElement.prototype.play` 를 가로채 막는다
  → 3초에 1회. 이 브라우저에서만 멈추고 방 데이터는 그대로. 스크립트보다 먼저 튼 영상은 페이지가 바뀐 3초 뒤 1.2초 동안 그리기 호출을 엿봐 찾는다.
  문서 안 영상(시트 · 핸드아웃) · 화상 채팅(srcObject) · `<audio>` 는 건드리지 않는다.

## 6. 검증 · 배포

- `node --check` → `bash tests/run.sh` (테스트 묶음 전부 · 이름을 주면 그것만). checktest의 bad=3은 의도된 것.
- 새 기능 · 고친 버그마다 `tests/`에 테스트를 더하고 `run.sh` 목록에 넣는다.
- 화면이 바뀌면 Playwright 스크린샷으로 직접 확인한다.
- 실제 Roll20에서 못 해 본 것은 그렇다고 말한다.
- 버전: `@version`과 `SCRIPT_VER`를 같이 올린다. 기능 추가 = 가운데 자리, 고침 = 끝자리.
- 사용자에게는 **GitHub 주소**로 준다 (2026-11-14 사용자 요청 — zip 은 열기 번거로움). 푸시한 뒤 이 주소를 알린다:
  `https://raw.githubusercontent.com/nireonyou-stack/claude/claude/hopeful-archimedes-j83l7a/userscript/roll20-layout2-allinone.user.js`
  푸시 직후에는 GitHub 이 브랜치 주소로 몇 분 동안 옛 판을 내준다 (`?v=` 를 붙여도 그대로 — 2026-11-14 확인).
  그래서 바로 받을 주소는 **커밋 주소**로 준다: `https://raw.githubusercontent.com/nireonyou-stack/claude/<커밋 해시>/userscript/roll20-layout2-allinone.user.js`
  — 거기서 설치해도 다음 업데이트는 아래 `@updateURL`(브랜치 주소)로 받는다.
  스크립트 머리의 `@updateURL` · `@downloadURL` 도 이 주소 (Tampermonkey 업데이트 확인이 여기서 받는다).
- 테스트는 Playwright(실행 환경에 깔린 것) + 정적 서버 `tests/serve.js`(127.0.0.1:8766). jQuery · Summernote 등은 `tests/package.json`의 npm 패키지.
